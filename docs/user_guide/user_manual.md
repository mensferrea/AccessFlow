# Руководство пользователя (User Manual)
## Проект: AccessFlow — Employee Access Management

### 1. Назначение системы
AccessFlow — автоматизированная платформа для централизованной подачи, согласования и исполнения заявок на получение доступа к внутренним банковским системам (АБС, ДБО, Процессинг, CRM, Хранилище данных, СУБД).

---

### 2. Сценарий: Подача заявки на доступ (Сотрудник)

1. **Авторизация в системе**:
   - Войдите в портал по корпоративной учетной записи.
2. **Выбор информационной системы и роли**:
   - Перейдите в раздел `Каталог систем и прав` (`GET /api/v1/systems`, `GET /api/v1/roles`).
   - Найдите необходимую систему (например, `CORE_BANKING - АБС Банка`).
   - Выберите требуемую роль (например, `Оператор РКО` или `Администратор БД`).
3. **Заполнение формы заявки**:
   - В поле **Обоснование** укажите производственную необходимость (не менее 10 символов, например: *«Перевод в отдел РКО согласно приказу №124»*).
   - При необходимости укажите срок действия доступа (поле `valid_to`).
4. **Отправка заявки**:
   - Нажмите кнопку **«Подать заявку»** (`POST /api/v1/requests`).
   - Система автоматически проверит ваш статус в кадровой системе (HRIS).
   - Если статус активен, заявке присваивается номер и статус `PENDING_MANAGER` (На согласовании у руководителя).

---

### 3. Сценарий: Отслеживание и отзыв заявки (Сотрудник)

1. **Просмотр статуса**:
   - В разделе **«Мои заявки»** отображаются все поданные вами обращения.
   - Текущие статусы:
     - `PENDING_MANAGER` — на рассмотрении у вашего руководителя;
     - `PENDING_OWNER` — на рассмотрении у владельца системы (для привилегированного доступа);
     - `PENDING_SECURITY` — на экспертизе в Службе ИБ;
     - `PROVISIONED` — доступ успешно предоставлен;
     - `REJECTED` — заявка отклонена;
     - `CANCELLED` — заявка отозвана вами.
2. **Отзыв заявки**:
   - Если потребность отпала или вы допустили ошибку при выборе роли, нажмите **«Отозвать заявку»** (`POST /api/v1/requests/{id}/cancel`).
   - Отзыв возможен в любой момент до завершения согласования.

---

### 4. Сценарий: Согласование заявок (Руководитель, Владелец ИС, Офицер ИБ)

1. **Входящие заявки**:
   - Перейдите в раздел **«Заявки на согласовании»**.
   - Ознакомьтесь с информацией о сотруднике, запрашиваемой роли, признаком привилегированности и обоснованием.
2. **Принятие решения**:
   - Для утверждения нажмите **«Согласовать»** (`decision: APPROVED`).
     - Для стандартной роли заявка сразу переходит к исполнению.
     - Для привилегированной роли заявка направляется следующему согласующему по маршруту.
   - Для отклонения нажмите **«Отклонить»** (`decision: REJECTED`).
     - **Важно:** при отклонении поле **«Комментарий»** является строго обязательным (не менее 5 символов).

---

### 5. Сценарий: Мониторинг и решение инцидентов (Администратор)

1. **Обработка ошибок исполнения**:
   - Если целевая система временно недоступна, система автоматически совершает до 3 попыток вызова API IAM.
   - В случае исчерпания попыток заявка переходит в статус `FAILED`.
   - Администратор устраняет причину сбоя и нажимает **«Повторить исполнение»** (`POST /api/v1/requests/{id}/retry`).
2. **Журнал аудита**:
   - Администратор и офицер ИБ имеют доступ к неизменяемому журналу `audit_logs` для расследования инцидентов и регулярного комплаенс-контроля.
