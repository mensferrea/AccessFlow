# Модель состояний заявки на доступ (Access Request State Machine)
## Проект: AccessFlow

### 1. Перечень состояний (States)

| Код состояния | Наименование | Описание | Финальное? |
|---|---|---|---|
| `DRAFT` | Черновик | Заявка сформирована, но еще не отправлена на согласование. | Нет |
| `PENDING_MANAGER` | На согласовании у руководителя | Заявка передана на рассмотрение непосредственному руководителю. | Нет |
| `PENDING_OWNER` | На согласовании у владельца ИС | Для привилегированного доступа: одобрено руководителем, ожидает владельца системы. | Нет |
| `PENDING_SECURITY` | На согласовании в ИБ | Для привилегированного доступа: одобрено руководителем и владельцем, ожидает службу ИБ. | Нет |
| `APPROVED` | Согласована | Все требуемые этапы согласования успешно пройдены. Готова к провижинингу. | Нет |
| `IN_PROVISIONING` | В процессе исполнения | Запрос отправлен в целевую систему/IAM, ожидается подтверждение. | Нет |
| `PROVISIONED` | Доступ предоставлен | Права успешно назначены в целевой системе через IAM. | Да (Успех) |
| `REJECTED` | Отклонена | Заявка отклонена на одном из этапов согласования с указанием причины. | Да (Отказ) |
| `CANCELLED` | Отозвана | Заявка отменена инициатором до момента финального согласования. | Да (Отмена) |
| `FAILED` | Ошибка исполнения | Ошибка при исполнении провижининга в IAM после исчерпания всех ретраев. | Да (Требует вмешательства) |

---

### 2. Матрица допустимых переходов (Transition Matrix)

| Исходное состояние | Целевое состояние | Событие / Триггер | Кто выполняет | Условие / Правило |
|---|---|---|---|---|
| `[START]` | `DRAFT` | Создание черновика | Сотрудник | Валидность полей формы |
| `[START]` | `PENDING_MANAGER` | Мгновенная подача | Сотрудник | `HRIS.status == ACTIVE`, нет дубликатов |
| `DRAFT` | `PENDING_MANAGER` | Отправка заявки | Сотрудник | Заполнены обязательные поля |
| `DRAFT` | `CANCELLED` | Удаление черновика | Сотрудник | - |
| `PENDING_MANAGER` | `APPROVED` | Одобрение руководителем | Руководитель | `is_privileged == false` |
| `PENDING_MANAGER` | `PENDING_OWNER` | Одобрение руководителем | Руководитель | `is_privileged == true` |
| `PENDING_MANAGER` | `REJECTED` | Отклонение руководителем | Руководитель | Заполнен `comment` (≥ 5 симв.) |
| `PENDING_MANAGER` | `CANCELLED` | Отзыв сотрудником | Сотрудник | Инициатор = текущий пользователь |
| `PENDING_OWNER` | `PENDING_SECURITY` | Одобрение владельцем ИС | Владелец ИС | Назначен владельцем `system_id` |
| `PENDING_OWNER` | `REJECTED` | Отклонение владельцем ИС | Владелец ИС | Заполнен `comment` (≥ 5 симв.) |
| `PENDING_OWNER` | `CANCELLED` | Отзыв сотрудником | Сотрудник | Инициатор = текущий пользователь |
| `PENDING_SECURITY`| `APPROVED` | Одобрение офицером ИБ | Офицер ИБ | Роль `SECURITY_OFFICER` |
| `PENDING_SECURITY`| `REJECTED` | Отклонение офицером ИБ | Офицер ИБ | Заполнен `comment` (≥ 5 симв.) |
| `PENDING_SECURITY`| `CANCELLED` | Отзыв сотрудником | Сотрудник | Инициатор = текущий пользователь |
| `APPROVED` | `IN_PROVISIONING` | Запуск задачи провижининга| Система (авто) | Немедленно при переходе в `APPROVED` |
| `IN_PROVISIONING` | `PROVISIONED` | Успешный ответ IAM | Система (IAM) | HTTP `200/201` от IAM API |
| `IN_PROVISIONING` | `FAILED` | Исчерпание ретраев / Ошибка| Система (IAM) | 3 неудачных попытки или ошибка `4xx` |
| `FAILED` | `IN_PROVISIONING` | Ручной перезапуск | Администратор | Устранена причина сбоя в IAM/целевой ИС |

---

### 3. Запрещенные переходы

1. Переход из любого финального состояния (`PROVISIONED`, `REJECTED`, `CANCELLED`) в любое другое состояние **категорически запрещен**.
2. Отзыв сотрудником (`CANCELLED`) из состояний `APPROVED`, `IN_PROVISIONING` запрещен (так как транзакция провижининга уже заблокирована и исполняется).
3. Переход в обход промежуточных согласующих (например, `PENDING_MANAGER` -> `PENDING_SECURITY` минуя `PENDING_OWNER`) запрещен бизнес-логикой движка.
