## Спецификация тест-кейсов (Test Cases Specification)

### 1. Функциональные тесты (Functional Test Cases)

| ID | Название | Предусловия | Шаги воспроизведения | Ожидаемый результат | Тип |
|---|---|---|---|---|---|
| **TC-FR-01** | Создание заявки на стандартный доступ | Сотрудник активен в HRIS | 1. Выбрать роль `ABS_OPERATOR` (is_privileged=false)<br>2. Заполнить обоснование (≥10 симв.)<br>3. Отправить POST /api/v1/requests | HTTP 201 Created, статус `PENDING_MANAGER`, запись в audit_logs | Позитивный |
| **TC-FR-02** | Создание заявки на привилегированный доступ | Сотрудник активен в HRIS | 1. Выбрать роль `DB_ADMIN` (is_privileged=true)<br>2. Отправить POST /api/v1/requests | HTTP 201 Created, статус `PENDING_MANAGER`, запланированы 3 шага | Позитивный |
| **TC-FR-03** | Создание заявки уволенным сотрудником | Статус сотрудника в HRIS = `DISMISSED` | 1. Отправить POST /api/v1/requests от лица уволенного | HTTP 403 Forbidden ("Сотрудник заблокирован или уволен") | Негативный |
| **TC-FR-04** | Предотвращение дублирования заявки | Уже есть активная заявка на роль | 1. Повторно отправить POST /api/v1/requests с тем же `role_id` | HTTP 409 Conflict ("Заявка на данную роль уже находится на согласовании") | Негативный |
| **TC-FR-05** | Согласование руководителем (Стандартный доступ) | Заявка в статусе `PENDING_MANAGER`, роль стандартная | 1. Руководитель отправляет POST .../approve (decision=APPROVED) | Заявка переходит в `APPROVED` -> сразу в `IN_PROVISIONING` -> `PROVISIONED` | Позитивный |
| **TC-FR-06** | Согласование руководителем (Привилегированный доступ) | Заявка в статусе `PENDING_MANAGER`, роль привилегированная | 1. Руководитель отправляет POST .../approve (decision=APPROVED) | Заявка переходит в `PENDING_OWNER` | Позитивный |
| **TC-FR-07** | Отклонение заявки руководителем с комментарием | Заявка в `PENDING_MANAGER` | 1. Отправить POST .../approve (decision=REJECTED, comment="Не соответствует грейду") | Заявка переходит в статус `REJECTED`, причина сохранена | Позитивный |
| **TC-FR-08** | Отклонение заявки без обязательного комментария | Заявка в `PENDING_MANAGER` | 1. Отправить POST .../approve (decision=REJECTED, comment=null) | HTTP 400 Bad Request ("При отклонении заявки комментарий обязателен") | Негативный |
| **TC-FR-09** | Отзыв заявки инициатором | Заявка в `PENDING_MANAGER` | 1. Сотрудник отправляет POST .../cancel | Заявка переходит в статус `CANCELLED` | Позитивный |
| **TC-FR-10** | Запрет отзыва уже согласованной заявки | Заявка в статусе `PROVISIONED` | 1. Сотрудник отправляет POST .../cancel | HTTP 400 Bad Request ("Невозможно отозвать заявку в статусе PROVISIONED") | Негативный |

### 2. Интеграционные тесты (Integration Test Cases)

| ID | Название | Шаги | Ожидаемый результат | Тип |
|---|---|---|---|---|
| **TC-INT-01** | Успешное исполнение через эмулятор IAM | Финальное согласование заявки | Сервис вызывает IAM POST /api/v1/iam/provision. Получен HTTP 201, статус `PROVISIONED` | Интеграционный |
| **TC-INT-02** | Повтор запроса с тем же Idempotency-Key | Отправка повторного запроса провижининга с тем же UUID | IAM возвращает существующий результат без повторного создания учетной записи | Интеграционный |
| **TC-INT-03** | Сбой IAM и переход в статус FAILED | Эмулятор IAM переведен в режим имитации 503 ошибок | Сервис выполняет 3 попытки, после чего заявка переводится в статус `FAILED` | Негативный интеграционный |
| **TC-INT-04** | Валидация XML интеграционного сообщения по XSD | Вызов метода валидации с корректным XML | Результат: `is_valid == true`, отсутствие ошибок валидации схемы | Интеграционный |
| **TC-INT-05** | Обнаружение нарушения схемы XML (XSD validation) | Передача XML с отсутствующим обязательным полем `SystemCode` | Результат: `is_valid == false`, получен список несоответствий XSD | Негативный интеграционный |
